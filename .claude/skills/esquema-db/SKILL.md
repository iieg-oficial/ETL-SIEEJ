name: esquema-db
description: Plantillas para las migraciones Flyway V1-V4 de un nuevo pipeline (foreign tables, catálogos, tablas principales y vista de integración).
---

## Cuándo usar

Después del EDA aprobado. Genera los SQL en `migrations/{flujo}/sql/`. Aplica con `just flyway-migrate {flujo}` y valida con `just flyway-info {flujo}`.

## Convenciones

Ver `database-rules.instructions.md`. Resumen: snake_case ES, prefijos `cat_`/`stg_`, FKs `{singular}_id`, PK `id`, `fecha_actualizacion` en tablas principales.

---

## V1 — Foreign tables a `cve_geo`

`migrations/{flujo}/sql/V1__foreign_tables.sql`:

```sql
CREATE EXTENSION IF NOT EXISTS postgres_fdw;

CREATE SERVER IF NOT EXISTS cve_geo_server
    FOREIGN DATA WRAPPER postgres_fdw
    OPTIONS (host '${cve_geo.host}', dbname '${cve_geo.dbname}', port '${cve_geo.port}');

CREATE USER MAPPING IF NOT EXISTS FOR CURRENT_USER
    SERVER cve_geo_server
    OPTIONS (user '${cve_geo.user}', password '${cve_geo.password}');

CREATE SCHEMA IF NOT EXISTS cvegeo;

IMPORT FOREIGN SCHEMA public
    LIMIT TO (entidades, municipios, localidades)
    FROM SERVER cve_geo_server INTO cvegeo;
```

## V2 — Catálogos

`migrations/{flujo}/sql/V2__catalogs_{flujo}.sql`. Omitir el archivo si el pipeline no tiene catálogos.

```sql
CREATE TABLE IF NOT EXISTS cat_{nombre} (
    id           INTEGER PRIMARY KEY,
    {nombre}     TEXT NOT NULL UNIQUE
);
```

- Si el catálogo tiene id natural (ej. CVE_INEGI) usar `INTEGER PRIMARY KEY` sin `GENERATED`.
- Si el id es interno, usar `GENERATED BY DEFAULT AS IDENTITY`.

## V3 — Tablas principales

`migrations/{flujo}/sql/V3__tables_{flujo}.sql`:

```sql
CREATE TABLE IF NOT EXISTS stg_{principal} (
    id                    INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    cve_geo_id            BIGINT NOT NULL,
    {catalogo}_id         INTEGER NOT NULL REFERENCES cat_{catalogo}(id),
    valor_x               NUMERIC,
    valor_y               INTEGER,
    fecha_actualizacion   DATE NOT NULL
);

CREATE INDEX idx_stg_{principal}_cve_geo ON stg_{principal}(cve_geo_id);
```

- `nullable` debe coincidir con `schemas.py`.
- Indexar FKs y columnas de filtro frecuente.

## V4 — Vista de integración

`migrations/{flujo}/sql/V4__views_{flujo}.sql`:

```sql
CREATE OR REPLACE VIEW v_{flujo} AS
SELECT
    s.id,
    e.entidad,
    m.municipio,
    c.{nombre}    AS {nombre},
    s.valor_x,
    s.valor_y,
    s.fecha_actualizacion
FROM stg_{principal} s
JOIN cvegeo.municipios m ON m.cve_geo_id = s.cve_geo_id
JOIN cvegeo.entidades  e ON e.id        = m.entidad_id
JOIN cat_{nombre}      c ON c.id        = s.{nombre}_id
{where_jalisco}
;
```

`{where_jalisco}` = `WHERE e.id = 14` solo si el pipeline es Jalisco-only.

Si el pipeline usa SCD Tipo 2: agregar `WHERE s.is_current = TRUE`.

## flyway.conf.example

```
flyway.url=jdbc:postgresql://localhost:5432/{flujo}
flyway.user=postgres
flyway.password=postgres
flyway.locations=filesystem:./migrations/{flujo}/sql
flyway.placeholders.cve_geo.host=cve_geo_host
flyway.placeholders.cve_geo.dbname=cve_geo
flyway.placeholders.cve_geo.port=5432
flyway.placeholders.cve_geo.user=cve_geo_user
flyway.placeholders.cve_geo.password=cve_geo_password
```

## Validación

```bash
just up-database
just flyway-migrate {flujo}
just flyway-info {flujo}
```

Errores de lógica → corregir el script existente, **no** crear nuevas versiones.
